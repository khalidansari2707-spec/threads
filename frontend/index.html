Operating Systems: Multithreading & Concurrency Syllabus

Comprehensive, clear conceptual foundation for Computer Engineering students covering thread lifecycles, memory architecture, mutual exclusion, and hardware execution models.

1. Process vs. Thread

A process is an independent program in execution with its own isolated virtual address space, file descriptors, and security context. A thread is the smallest schedulable unit of CPU execution within a process. Multiple threads share the process's code, data, and heap segments, but each thread has its own Program Counter (PC), Registers, and Call Stack.

2. Concurrency vs. Parallelism

Concurrency is about dealing with multiple things at once (structure, time-slicing on 1 core). Parallelism is about doing multiple things at once simultaneously (execution across physical CPU cores). As Rob Pike noted: "Concurrency is about program structure; parallelism is about execution."

3. Thread Lifecycle

A thread transitions through 5 primary OS states: New (created in memory), Ready (in OS run-queue waiting for CPU time), Running (executing instructions on a core), Waiting / Blocked (waiting for I/O or mutex lock), and Terminated (finished execution, resources reclaimed).

4. Race Conditions & Data Races

A race condition occurs when the output of a program depends on the non-deterministic interleaving or timing of thread executions. In C++, a data race occurs when two or more threads concurrently access the same memory location, at least one access is a write, and no synchronization is used. Under ISO C++, data races cause Undefined Behavior (UB).

5. Mutex & Critical Section

A critical section is a code block accessing shared mutable resources. The Critical Section Problem requires three guarantees: Mutual Exclusion (only one thread at a time), Progress (selection of next entrant cannot be postponed indefinitely), and Bounded Waiting (no thread starves waiting for access).

6. Atomic Operations

Atomic operations (e.g., std::atomic) are executed as single, indivisible CPU instructions at the hardware bus level (such as LOCK CMPXCHG on x86). They eliminate lock overhead, avoid OS context switching, and guarantee thread safety without deadlocks.

About MultiCoreX System

MultiCoreX is an educational Operating Systems visualization and performance benchmarking software designed to demonstrate modern C++ multithreading, synchronization primitives, thread pools, and race conditions.

Technical Stack Architecture:

  • C++ Backend Engine: ISO C++17, compiled with Microsoft Visual Studio (MSVC) Optimizing Compiler.
  • Multithreading Primitives: Standard C++ Thread Library (std::thread, std::mutex, std::condition_variable, std::atomic, std::chrono).
  • HTTP Server & API Layer: Lightweight embedded cpp-httplib with nlohmann/json serializer.
  • Interactive Frontend: HTML5, CSS3 Custom Properties (Vanilla CSS), Vanilla JavaScript ES6+, and Chart.js.
